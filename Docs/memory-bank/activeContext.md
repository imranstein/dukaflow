## Worth knowing before you touch anything

- The stack is newer than most tutorials: **Laravel 13, Filament 5, Livewire 4, Pest 4**. Filament 5 moved forms to `Filament\Schemas\Schema` and actions to `Filament\Actions\*`, and tables use `recordActions()` / `toolbarActions()`. Generate Filament classes with artisan rather than writing them from memory.
- `make:filament-resource` infers the target directory from existing resources, not from the model namespace. It put the Distribution resources under Catalog; the arch test caught it. Check where generated files land.
- Pest closures break Larastan: `$this->foo` inside `it()` resolves to `TestCall`. Use the `Pest\Laravel\*` functions and local variables instead of `beforeEach` properties.
- **`client_id` lives on the row, not only in the audit log.** `OrderWriter::startDraft()` takes an optional `clientId` that has to be threaded all the way from the HTTP payload through `OrderIntake` — it's easy to wire the idempotency check correctly (via `SyncAuditLog`) and still leave the order's own `client_id` column null, because idempotency working correctly doesn't prove the column got set. Caught by hand in the browser, not by a test, on the first live run.
- **`crypto.randomUUID()` is not a ULID.** `client_id`/`device_id` are `char(26)` ULID columns; a 36-character UUID either truncates or 422s against `PullSyncRequest`'s `max:26`. There's a hand-rolled Crockford-base32 `ulid()` in `resources/js/rep/ulid.js` for exactly this — use it, not the browser's built-in UUID generator, anywhere a client_id or device_id is generated.
- **"Visited today" cannot be derived from the sync queue.** A completed visit's whole purpose is to leave the queue once it syncs, so a queue-only check makes the checkmark vanish the moment sync succeeds. It has to be its own persisted, date-scoped record (`visited:YYYY-MM-DD` in IndexedDB's `meta` store), written at capture time and never cleared by a successful push.
- Laravel's default guest-redirect middleware calls `route('login')` unconditionally; this app has never had that route (Filament owns its own auth flow, the rep interface has `rep.login`). `bootstrap/app.php` overrides `redirectGuestsTo()` to point at `rep.login` — the only generic guest-auth surface this app has outside Filament.
- The app's `shouldRenderJsonWhen()` only renders JSON under `/api/*`; the sync endpoints live at `/api/sync/*` for exactly that reason, on the plain `web` middleware group (session + CSRF), not a separate API guard — see ADR-002 §8.
- **A "changes since" feed being cursor-correct says nothing about whether it's scope-correct.** `SyncFeed::pull()` took `(entityType, cursor, limit)` with no notion of who was asking, and every test proved the delta logic worked while nobody wrote a test proving one rep couldn't see another's customers — because both look identical from inside a single-rep test. `$salesRepId` is now a required (nullable-but-fails-closed-on-null) parameter on the interface itself, and `SyncFeedTest.php`'s "never hands one rep another rep's book" test is the shape to copy for the next feed like this: two reps, two routes, assert the wrong one's data never appears — not just that the right one's does.
- **On alpine, `apk del <ext>-dev` can silently take the runtime `.so` with it.** `icu-dev` pulls in `icu-libs` as a dependency; nothing else in a minimal PHP image references `icu-libs` directly, so deleting `icu-dev` after building the `intl` extension removes `icu-libs` too, and `intl` fails to load at runtime with a missing `libicuio.so` — found by actually running the sequence in isolation, not by reading the Dockerfile. Fix is `apk add --no-cache icu-libs` again, by name, right after the `apk del`. Worth re-checking for any other `*-dev` package added later in `docker/Dockerfile`; this isn't unique to icu, just what actually got tested.
- **A Dockerfile that never fully builds locally can still ship a real, checkable bug — check the parts you can.** The `composer-deps` stage's platform check (`filament/support` needs `ext-intl`) was never exercised by any of the isolated per-stage checks done while the local machine was disk-constrained, because none of them happened to run `composer install` against the real lock file in the real `composer:2` image. A narrower, cheaper check (`docker run composer:2 composer install --dry-run`) would have caught it without needing the full multi-stage build at all — worth reaching for that kind of targeted check before assuming "I verified the parts I could" covers everything a full build would have.
- **Filament's `CodeEntry` needs `phiki/phiki`, which isn't in this project's dependency list.** It's a real composer dependency of `filament/infolists`, not bundled — using it 500s with `Class "Phiki\Phiki" not found` the first time a page actually renders one, which a static check won't catch. For read-only JSON display, a plain `TextEntry::make(...)->html()->state(fn ($record) => '<pre>'.e(json_encode(...)).'</pre>')` needs nothing extra.
- **`TextEntry` treats array state as a list of items, not one value.** `Arr::wrap($state)` then a `foreach`, one `formatStateUsing` call per element — right for tag/badge lists, wrong for a single JSON blob, and it fails oddly: `formatStateUsing(fn (?array $state) => ...)` gets called with each *leaf scalar* of the array (a stray `int`, a stray `string`), not the whole array, so the type error reads like the wrong data arrived rather than what it actually is — the wrong *shape* of state. Route a whole-payload display through `->state(fn ($record) => $alreadyRenderedString)` instead, so it never enters `formatState()`'s per-item path at all.
- **IndexedDB is per-origin, not per-user.** A PWA with client-side auth state (`window.DUKAFLOW_REP`) and an offline queue needs that queue namespaced by the logged-in user's id, not just by the app's name — otherwise a device two people log into in sequence hands the second person the first person's unsynced data. `resources/js/rep/db.js`'s `DB_NAME` is `dukaflow-rep-${repId}` for exactly this; if a second PWA surface ever gets built here, it needs the same namespacing from the start, not bolted on after a review finds it missing.
